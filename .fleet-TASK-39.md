# Task (issue #39, slice: budget accounting + enforcement)

Master HEAD is `f9d4e10`. Work from there. Edit files in place in this checkout, do not create branches.

## Context
- Per-run usage already exists post-run: the audit manifest (`src/audit.ts`) sums engine usage into `manifest.usage` (tokens, costUsd when the engine reports cost; Pi reports nothing usable).
- Concurrency landed in #149 (`src/capacity.ts`, per-node maxConcurrent, retryable "no-capacity"). Mirror that shape and quality.

## Exact change
1. Config: new `budget` block (schema-safe, optional): `dailyCostUsd`, `dailyTokens`, optional `perDispatchCostUsd` / `perDispatchTokens`. Validate at config load.
2. Ledger: record each finished fleet run's `usage` (from the audit manifest) on its ledger entry when the manager reconciles/polls a finished run. Account runs to the day they START (UTC) in the ledger.
3. New `src/budget.ts`: pure helpers that read the ledger and answer "can this dispatch start?" — total per-day cost/tokens already spent + this run's declared cap vs the configured caps. Export a small typed result `{ allowed: boolean; reason?: string; spent?: { costUsd?: number; tokens?: number } }`.
4. Enforcement: `fleet_dispatch` checks the budget BEFORE launching; on exhaustion returns a retryable result `"budget-exhausted"` shaped like `"no-capacity"` (same result family, same retry semantics). `perDispatchCostUsd`/`perDispatchTokens` overrides in dispatch params take precedence over config defaults.
5. `fleet_iterate`: count its own iterations against the same total budget (each iteration is a run seed); when the day budget is spent, stop with the no-progress/escalation path annotated "budget".
6. `fleet_capacity` (or the status tool that shows slots) also shows today's budget spend, remaining, and per-run caps, so the state is visible (issue #39 acceptance).
7. Daily budget resets at 00:00 UTC. Do not build persistence for the daily window beyond what the ledger already gives you — derive the day's spend from ledger entries.
